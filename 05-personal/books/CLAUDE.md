# Book Notes — Agent Instructions

This folder contains [Reader]'s reading notes. Each book gets its own `.md` file with notes on characters, magic systems, worldbuilding, factions, plot threads, and open questions.

The goal is to have a reference to check while reading — "wait, who was that character again?" or "how does this magic system work?" — without getting spoiled on what comes next.

## CRITICAL: Web Search Requirement

**You MUST use web search for any factual claims about a book.** Do not rely on pre-trained knowledge alone. Books may have details your training data gets wrong, conflates with other entries in a series, or misremembers entirely.

**Always search before:**
* Answering questions about specific characters, their motivations, or relationships
* Explaining magic systems, political structures, or worldbuilding details
* Clarifying plot points or the sequence of events
* Describing factions, organizations, or power structures

**Acceptable sources:**
* Official author sites and publisher pages
* `en.wikipedia.org` — plot summaries (use carefully, often contains full spoilers — filter to relevant sections)
* Fan wikis specific to the series (e.g., Fandom wikis)
* `goodreads.com` — reviews and reader discussions
* `storygraph.com` — reviews

**If you can't find reliable information:** Say so clearly rather than guessing.

## CRITICAL: Spoiler Policy

**No spoilers beyond where the reader currently is in the book.** Each book's notes file has a `Progress` section at the top that tracks how far the reader has read (chapter number, percentage, or section).

* If asked about a character, event, or concept not yet encountered at the reader's current progress: **withhold it entirely**
* If asked about something the reader has already read past: explain freely with full context
* Do not hint at future developments, twists, betrayals, deaths, or revelations
* Do not say things like "you'll find out more about that later" or "that becomes important" — these are spoilers by implication

**Exception:** If the reader explicitly asks to be spoiled ("spoil me", "what happens next", "tell me the ending"), answer freely.

**Series spoilers:** If a book is part of a series, do NOT reveal information from later books unless the reader has marked them as read. Treat each book's progress independently.

## When the Reader Gives a Reading Update

The reader will often give quick updates ("just finished chapter 12", "I'm at the part where X happens"). When this happens:
1. **Search first** — verify the details before responding
2. Update progress in the book's notes file
3. Add any new characters, concepts, or plot threads that are now fair game
4. Offer brief context or connections to earlier events if relevant
5. Keep the response brief unless more detail is asked for

## File Structure Per Book

Each book file should follow this general structure:

```markdown
# [Book Title]
**Author:** [Name]
**Series:** [Series name, Book X of Y] (if applicable)
**Progress:** [Chapter X / X% / Section name] — update this as the reader reads

## Characters
* **[Name]** — role, first appearance, key details known so far

## Magic System / Powers
* How it works, rules, limitations (as understood so far)

## Worldbuilding
* Political structures, geography, factions, history

## Plot Threads
* Open questions and unresolved threads at current progress

## Notes
* Reader's observations, theories, questions
```

## CRITICAL: Verify Logical Consistency

Before writing or updating any notes, **re-read what you've already written about the system's rules**, then check that every claim is consistent with them. Magic systems, power structures, and worldbuilding often have counterintuitive logic (e.g., ceding power makes you *weaker*, not stronger). Getting cause and effect backwards in a notes file is worse than having no notes at all — the reader is relying on these as a reference while reading.

Specific checks before writing:
* If describing a character as strong/weak/unusual, verify *why* against the rules already documented in the notes file
* If a system involves trade-offs (give X, lose Y), make sure descriptions of characters reflect the correct side of the trade-off
* If you're uncertain about how a mechanic applies to a specific character, say so rather than guessing the direction

## Tone

Straightforward and reference-oriented. This is a lookup tool, not a book review. Prioritize clarity and accuracy over style. When explaining something, give enough context to jog memory without over-explaining.
